Make ``shared-release-schedule`` bump levels configurable through ``minor-fragments`` and ``major-fragments``, which take comma-separated towncrier types, and the fragment discovery configurable through ``newsfragments-dir`` and ``newsfragments-extension``.
Previously only ``newsfragments/*.feature.rst`` raised the minor and nothing raised the major, so a ``break`` fragment was released as a patch, and a repository keeping markdown fragments or using towncrier's ``directory`` setting was invisible to the planner.
Defaults reproduce the previous behaviour. On a pre-1.0 project list the breaking type under ``minor-fragments`` and leave ``major-fragments`` empty.
Fragments are now matched as ``<dir>/*.<type>.<extension>``, so a ``README.rst`` sitting in the newsfragments directory no longer counts as a fragment.
With ``newsfragments-required`` enabled, an empty newsfragments directory still skips quietly, but a missing directory or fragments found only under a different extension now fail the run, as such a repository would otherwise never release.
